# FacultyMind Architecture & Engineering Handover
**Date**: April 4, 2026

This document is a comprehensive technical handover detailing the architecture, database schemas, and codebase modules constructed during the marathon Sprint 3 & Sprint 4 engineering session.

---

## 1. Context & Objective Summary
The goal was to execute **Sprints 3 & 4 (Email Intelligence & Memory Engine)** natively into the FacultyMind local-first Electron application without relying on external cloud databases like Supabase, in order to maintain maximum privacy and zero-latency performance for the professor's Vault.

All work has been strictly implemented in `SQLite` using `better-sqlite3`, paired with robust AI NLP logic driven through Claude/GPT4o via `@anthropic-ai/sdk` and `openai`.

---

## 2. Sprint 3: Email Intelligence Module

We bypassed static regex rules and implemented a completely dynamic **Natural Language Email Rule Engine**.

### Key Additions & Files:
1. **`src/modules/email/email-classifier.js` (Updated):**
   - We upgraded `PROMPT-003`. Instead of just bucketing categories, the payload now enforces an explicit `priority` constraint (`HIGH`, `NORMAL`, `LOW`) allowing FacultyMind to instantly flag messages requiring urgent attention (like from the Dean or students).
2. **`src/modules/email/rule-engine.js` (NEW):**
   - The core NLP rule compiler. It passes user statements like *"Snooze advertisements today"* to an AI prompt (`PROMPT-004`) which generates deterministic JSON schema containing `allow_categories`, `snooze_categories`, `specific_senders`, and `duration_hours`.
   - The rule engine commits this directly to `faculty_rules` and `vip_senders` SQLite tables.
3. **`src/modules/ai/module-router.js` (Updated):**
   - The `EMAIL_RULE` intent was hooked up securely to the new Rule Engine, closing out the entire user-to-DB instruction loop.
4. **`src/modules/email/notifications.js` (Updated):**
   - The 5-minute background polling `setInterval` was completely overhauled.
   - **Bypass Logic:** Emails from VIPs or emails flagged as `HIGH` priority instantly bypass all rules and strike UI notifications immediately.
   - **Suppression Cache:** Emails that match a user's snooze rule are quietly caught and placed in an in-memory `suppressedQueue`.
   - **EOD Summary:** A secondary `setInterval` checks the time; at exactly 5:00 PM, an OS notification fires summarizing exactly how many low-priority emails were held back from distracting the professor during the day.

## 3. Sprint 4: The J.A.R.V.I.S Protocol (Memory Engine)

The largest architectural shift for FacultyMind ensuring the AI acts proactively rather than passively waiting for exact keyword commands.

### Key Additions & Database Overhaul:
1. **`src/database/migrations/001_init.js` (Updated):**
   - We destroyed the old `faculty.db` instance to cleanly implement the massive AI memory footprint schemas:
     - `faculty_profile`: Key/value store for hard preferences (quiet hours, department rules).
     - `behavioral_memory`: Tracks subconscious or observed behaviors.
     - `faculty_rules_memory`: Similar to email rules, but generalized to universal application control.
     - `ai_reflections`: The AI's internal scratchpad where it stores its daily cognitive learning.
     - `memory_log`: Audit trail for privacy.
2. **`src/modules/memory/memory-manager.js` (NEW):**
   - An I/O interface that dynamically aggregates the tables above into an 800-token contextual "Memory System Prompt Block" utilizing `.buildContext()`.
3. **`src/modules/ai/model-router.js` (Updated Context Injection):**
   - `buildSystemPrompt()` was converted to `async`.
   - **Environment Context:** Before ANY prompt hits an LLM, FacultyMind automatically pulls:
     - The current exact computer Date & Time.
     - The professor's *next immediate class* dynamically queried from the `schedule` table.
   - The AI is fundamentally aware of reality surrounding the prompt, answering questions differently strictly based on the time of day.
4. **`src/modules/ai/proactive-engine.js` (NEW):**
   - A hidden `PROACTIVE_GREETING` engine. 
   - When the Electron app transitions into the `ready-to-show` state, the Proactive Engine silently fires a prompt assessing the Memory Block and Environment Context.
5. **`src/main/main.js` & `preload.js` (Updated):**
   - Added `ipcRenderer.on('ai:proactive')` hooks.
   - If the AI identifies an urgent action item upon load, it immediately streams a message into the `chat.js` renderer UI unprompted (e.g., *"Good morning Professor. Your 10 AM OOP class is in 15 minutes, but you have 2 urgent emails from students."*).
6. **End-of-Day Machine Learning Loop:**
   - Hooked to `app.on('window-all-closed')`. When the professor fully shuts down the application, the AI runs one final hidden operation. It reflects on the day's events, summarizes new behavioral patterns, and commits a journal entry to `ai_reflections` to ensure it starts tomorrow smarter than today.
